# Проверка боя — issue #2, 13.11.2026

## Ручная оценка

Игра запущена на Windows, Godot 4.7.2 stable, Compatibility/OpenGL, NVIDIA GeForce RTX 4060 Ti. Пользователю передан список: бой у колонны и стены, камера сбоку, отход во время оранжевого замаха, победа, поражение и R. Ответ пользователя: «не заметил ошибок». Отдельных замечаний по балансу, попаданиям, читаемости замаха и камере не поступило. Это оценка пользователя текущей арены, а не результат headless-теста; длительность сессии и подробные действия не фиксировались.

Ассистент отдельно осмотрел стартовый вид арены и освобождение курсора через Esc. Полное прохождение ассистентом не заявляется.

## Исправление по проверке ввода

В обработке ввода обнаружено: щелчок захвата после Esc также становился командой атаки при следующем физическом кадре. Теперь первый щелчок только захватывает курсор, следующий начинает удар. Команда удара обрабатывается в `_unhandled_input`, чтобы потреблённый щелчок не запускал её через опрос глобального состояния Input. Баланс и канон не менялись.

Пользователь проверял сборку до этого небольшого исправления. Новое поведение проверяется отдельно регрессией через события мыши в Godot с графическим backend; это автоматическая проверка, не повторная ручная оценка пользователем.

## Автоматические проверки

- Импорт редактором в headless без ошибок.
- `tests/smoke.gd`, `tests/combat.gd`, `tests/navigation.gd`: 0 ошибок, код завершения 0. После окончательного изменения регрессии ввода `combat.gd` повторно пройден в headless и с графикой: 0 ошибок, код 0.
- Основная сцена: headless запуск 120 кадров без ошибок, код 0. Графический прогон `combat.gd` использовал OpenGL 3.3 / RTX 4060 Ti; это автоматический тест с рендерером.
- Основная сцена с графическим рендерером: 180 кадров без ошибок, код 0.
- Регрессия ввода проверяет щелчок захвата без атаки, следующий щелчок с атакой и отключение ввода. Headless не поддерживает захват мыши: две проверки, требующие захваченного курсора, явно пропускаются; их выполняет отдельный графический прогон `tests/combat.gd`.

## Ограничения

Геометрия, цвета и баланс остаются прототипом. Проверка не заменяет приёмку v0.2.0 (#18), экспорт Windows или проверку длительности пролога. PR по задаче #2 зависит от навигации из PR #24; его следует переносить на main после включения зависимости.
